# 两大节奏配套开发流程 · 11B 交办简报(2026-08-20)

> **缘由**:创始人 18:40 直令(原话档逐字):「因为这是第1次,我拉一个11B-来信开发流水线的窗口,咱们的开发流程好像也要跟着改变。现在是版本讨论-执行2个大节奏,跟以前完全不一样,需要配套的开发流程。」
> **给谁**:创始人将开的 11B-来信开发流水线窗口。上线后先按注册表纪律自报自更(名字自证读 `sessions/<自身PID>.json` 的 `name`),再读本简报与关联档。
> **本简报是需求侧输入,⛔ 方案**——配套流程怎么设计归 11B 起草,拍板归创始人,方案窗口供裁定与需求澄清。

## 一 两大节奏是什么(需求侧描述,权威=版本总纲 §七 与原话档当日 §三)

**节奏一:版本讨论(方案期)**——封盘后进入。特征:
- 指挥链=创始人→方案窗口→执行窗口,**动作触发源仅限点名消息**;执行窗口停活待命,⛔ 自提下件/自发盘点/成流送裁(创始人 18:35 直令,专项指挥链条条文备稿在看板 18:35-18:37 条);
- 开发冻结至方案落定;活口=热修+扎实化(扎实化配对判据见总纲 §七之三);
- 产出形态=底座/方案包(一件一档)/落定判据栈四层(§七之二)/scope 清单;
- 「落定」判据=不在讨论现场的人照它能做出来;开发发车=整版方案齐后,发车令归创始人。

**节奏二:执行(开发期)**——整版方案齐+创始人发车令后进入。特征:
- 现行流水线形态照转(双轨+独立验收+ff-only+看板台账),叠加 A 方案定稿项(分支命名/CHANGELOG 追行/热修 v0.y.z/发版 Release——五点待创始人拍,见 [[来信平台-代码管理方案-讨论稿]] §四);
- prompt 全部来自方案期落定的方案包(试写检验产物 ⛔ 直接发车,须另存正式 prompt 走 kickoff)。

## 二 交办给 11B 的面(需求清单,颗粒度归 11B 定)

1. **节奏状态机**:方案期/开发期怎么切换、谁宣布、落在哪里让所有窗口与工具可读(现状=散在看板与消息里,窗口重生后要靠读库拼);
2. **方案期的窗口姿态入指导**:dispatch/relay 在方案期的默认姿态与触发源写进流水线卡(把 18:35 备稿条文化,⛔ 只靠方案窗口口头传达——本轮已实测口头传达在换班后必然失传);
3. **扎实化活口的发车通道**:方案期内扎实化片怎么发(codex 执行窗口的拉起口径、与「方案完成后拉起」半边的衔接);
4. **A 方案定稿后的落地面**:CHANGELOG 追行工序放进哪个环节、分支命名规范入 kickoff 卡、Release 步骤入 deploy 卡;
5. **换班/交接机制对两节奏的适配**:方案期换班交接包该带什么(与开发期不同——本轮实测:方案期口径变更频率远高于开发期,交接包的口径快照极易过期);
6. **真实信息源的生成与刷新机制**(创始人 18:48 直令增补):开发时 AI ⛔ 每片重核代码库,要有可信的「真实信息源」——现有胚胎=六张机器生成事实表(`索引/生成/`,laixin_facts_export.py)+CodeGraph+模块 README+边界契约,prompts 宪法头已要求先查表;缺口=**模块视角汇总**(表按维度切,AI 开发某版块要跨表拼)与**业务规则层**(逻辑规则活在人写档里会过期,机器生成不了)。信息源的**形态设计归方案窗口 B 件**(模块事实页方向),**生成器扩展与「每片合并后刷新」工序归 11B**——刷新不进流程,信息源就是下一个「静默过期的表」。
