# 11C · 圆桌总纲(机制的家;wiki 性质,改判即更新,沿革记 [[11C-优化台账]])

> **成立依据**:创始人 2026-08-20 晚本窗口(11B)当面五轮定向后「**我认可,动手吧**」(原话逐字与时刻锚全在 [[11C-设立沿革与创始人原话-20260820]]);设计出处=[[来信平台-11C多模型圆桌方案稿-20260820]](已 superseded 入本纲)+[[来信平台-多Agent对话模式调研摘要-20260820]](业界实查十条可搬结论)。
> **一句话**:11C=方案期的多模型黑板圆桌——所有席位对着同一份档讨论,盲答防锚定、匿名防偏好、强制分歧防附和、外证防集体盲区、创始人拍板防假共识。

## 〇 定位与边界

- **11C=版本间机制**:只管「封盘确认→发车令」一段;开发期内方案窗口照旧按片滚动定稿(版本总纲 §一.1 防瀑布条不动,⛔ 把所有方案都塞进 11C);
- **两个目的两份产出**(创始人原话:只有 2 个目的):①**版本更新账**——把上一版(如 V0.1)更新清楚(封盘包:tag+CHANGELOG 版本段+刷新后事实表+底座更新);②**下版方案**——把下一版(如 V0.2)讨论清楚(发车包:scope 在册清单+方案包群+试写检验通过标记;正式 prompt 由 dispatch 开发期按 kickoff 以检验产物为底稿另存写就,⛔ 圆桌代写)。两包均落知识库,是 11C↔11B 的全部接口;判据栈「不在讨论现场的人照它能做出来」(版本总纲 §七之二)即接口质量标准;
- **承载=方案窗口现任(主持/聚合席)+relay(三职常设服务位:书记员·调研归口·质疑席,创始人 2026-08-20 晚拍「先这样干起来」)**,不新增常驻窗口;其余席位一次性应召(同验收窗口形态);
- **信息拓扑铁律**:11B 靠隔离保安全(独立验收 ⛔ 共视),11C 靠共视保质量(黑板圆桌 ⛔ 信使转述)——⛔ 互相串味;
- **工程硬依据**(⛔ 当偏好重议):三引擎中仅 claude 有 SendMessage,codex 与 kimi 均无——落盘共享档+`dmsg` 门铃是三家唯一共通通道,黑板是必然选择;
- **运营形态=流水席**(创始人 2026-08-20 晚定向,首局 R2 期间;原话逐字=沿革档 §二):圆桌**串行快节奏连续开局**——一局收口即开下一局,与 11B 活口通道**双流并行**(议题流推进下版方案+扎实化片流踩实上版);经济性依据=座席 token 成本远低于串行确认往返的协调成本(首局实测:派题至开牌约 10 分钟出三卷带判据实料);**三边界**(11B 解读,标注待实证/待拍):每局仍只经创始人两落点(R0 批框架/R4 裁决)⛔ 绕过;判据栈质量门不因提速降;**并行多局=候选**,待首局复盘与书记员载荷实证后再议 ⛔ 因产能富余即开。

## 一 圆桌协议(四段封顶)

| 段 | 动作 | 关键纪律 |
|---|---|---|

| **R1 盲答** | **书记员(relay)按间接指针法派题**(首局 R4 拍板成文,替换原 `dmsg` 条文——`cmd_dmsg` 硬编码投派工窗口且 `laixin-11c` 在 laixin-lane 管辖外,照旧条文必卡):①书记员生成派题正文(**零代号**,只含议题档路径+纪律)与每席一份**不可猜随机文件名**的一次性取号文件(内容=该席代号,存 `~/.laixin-11c-seal/`,SystemRandom 分配 ⛔ 按席位顺序对号);②dispatch(窗口层)只搬运「窗口→取号路径」**⛔ 打开取号文件 ⛔ 记录路径**(**🔁 双盲射程收窄 2026-08-21,方案窗口十九任裁;失败样本=局五 R1「送达三证深读画面」与「搬运层 ⛔ 见代号」结构性对撞,dispatch 主动自报**:双盲**核心线=主持与各席 ⛔ 见任何他席归属,零松动**;搬运层送达深读中不可避免见席位自述代号——小席数局下等效见全映射,如实 ⛔ 粉饰——处置=**看到即止:⛔ 记录 ⛔ 转述 ⛔ 写入任何公开记录 ⛔ 开牌前向任何人(含书记员与主持)提及**;兜底=P5 公开面代号零命中机器核照旧;⛔ 因搬运方已自觉做到便不入条文——靠自觉的步骤在流水线里等于不存在);③各席凭自己文件取号,提案头首行写「已取号」,**书记员收卷时删除取号文件(阅后即焚)**;④派题令必含**末行契约**要求。各提案席**独立**读全量材料、写提案落 vault 外暂存区 `R1-<代号>.md`;书记员收齐、**去署名**(署名=任何能反推席位的标识,**含视角标签**——首局实测收窄)后一次性贴入议题档=**开牌**并 kb-commit——**主持只见代号 ⛔ 见署名(双盲闭环)**。⚠️ **材料态随实际送达冻结**(⛔ 派题令时刻):送达后新增材料=各席材料态不一致,一律等 R2 走在局广播或 R4 后 | ⛔ 开牌前读他席文件(派题令写明);盲答是防锚定/从众最有证据的单一措施;提案席可标「**此处需范本,我不硬造**」出调研任务单;**claude 引擎席位的派题令额外含 ⛔ SendMessage 讨论本议题句**(三席通信能力不对称,禁令只需给有能力破戒的席——首局书记员立);**全向门铃(开牌通知/在局广播/质疑召集)预写同用间接指针形态,首次使用前跑全链演练**(D2 拍板) |
| **R2 互评** | 各席读全部提案(**匿名代号甲/乙/丙**),输出「分歧点清单+对方比我强的点+我可能错在哪」,落 `R2-<代号>.md`;**书记员去署名贴入分歧区并 kb-commit(与 R1 同形)**;**事实类分歧**(谁对属可查证)⇒ **relay 点状快查**或经调研归口派点状调研,当场裁决销分歧 | **强制分歧输出**:⛔ 空泛同意;无分歧必须列「我核对了哪几点」;匿名专治自我偏好与厂牌偏好 |
| **R3 修订合稿** | 有分歧的席修订一轮(可选);主持合稿=**共识区+分歧区(各方理由并陈)+待拍点清单** | 聚合者与提案者分离;**全体一致 ⇒ 强制加一次质疑轮**——**质疑席默认=relay**(甲级可临时加点一次性 Fable 窗口加码)——共识≠正确 |
| **R4 裁决** | 创始人逐点拍(人类节点 2),原话照录入档;**呈拍自带白话层——行话版留档、白话版上桌**(局三 R4 成文,实证=局二「6点我都看不懂」);结论迁权威位(裁定池/方案包/总纲),**书记员执行归档**(标 archived+迁移指针)、**揭示代号映射**并采集复盘行数字入优化台账 | 终止判据三层缺一不可=段数封顶+分歧清单清空或余项标「待拍」+创始人拍;⛔ 以全体一致为终止依据 |

- 创始人在任何段有**插话权**(interrupt 式),⛔ 逐轮当主持(那会退化成串行问答);
- **主持下场机制**(方案窗口第十七任补,创始人认可轮采纳;与深度参与换人判据同源):主持对议题本身有强立场时,可申请让渡主持席、下场当提案席——本场主持由创始人指定代席(可为一次性 Fable 窗口);⛔ 既主持又提案;
- **授权-2 圆桌内暂停**(静态审查 P-4,方案窗口自提自限):圆桌议题射程内主持 ⛔ 行使授权-2 直裁(直裁会蚕食「创始人拍板防假共识」兜底)——可直裁子点列入待拍清单标「建议按授权-2 处置」,创始人 R4 一并过;**圆桌外的日常裁定照旧**;
- **11B 回避条**(静态审查 §三.4,方案窗口采并补判据):11B 坐第三提案席时,凡议题结论会**修改 11B 维护的卡或工具仓**即算「提案自己的射程」——该类议题 11B 让席,由一次性 Fable 窗口顶替;换席后 11B 转服务位应召供料照常(供料不合议,与「relay 快查供料 ⛔ 裁」同构)。

**relay 三职边界四条**:①**起席收席(tmux 窗口层)仍归 dispatch**(窗口管理归口不变),relay 只管内容层的派题与收卷;②relay 深度参与某议题时,质疑席按既有深度参与判据换人;③三职产物全落盘——托管席随时重生,新任凭档即续(既有「派 relay 的活可落盘可中断」纪律的圆桌形态);④**裁定权不随转**:relay 快查供料 ⛔ 裁,裁定仍归方案窗口(授权-2)与创始人。

**议题分级**(开场权:主持建议级别,创始人批):**甲级**(版本 scope/架构/初心)=全席四段;**乙级**(一件一档方案包)=提案二席(按议题性质从三席选二)+合稿,段可并;**丙级**(单点裁定/小事)=**不开圆桌**,走现行裁定池与授权-2——圆桌 ⛔ 替代裁定机制。成本口径:terra=priority 计费、k3=max thinking,甲级才全席。

## 三 调研席(外证通道;创始人 2026-08-20 增设直令)

**原理**:盲答/匿名/异构防的是**个体偏差**;调研席治的是**集体盲区**——所有模型共享训练数据先验,合议只是在平均,平均产生不了尾部的品味与新解。来信有新创意但也大量借鉴(创始人原话),外证=把人类的优秀实践接进圆桌。**AI 擅长拆解范本为什么好、把范本适配到自己场景;不擅长无中生有地造好方案**——调研席供「借鉴」,合议席做「适度调整」(13:46 直令的分工版),拍板归创始人。

**对点调研 ⛔ 大目标一次性大扫**(创始人点名的旧病:以前调研/信息员都为一个大目标,没有对点)。三个挂点已入 §一 协议:**R0 前置调研(🔴 每局必做的硬前置 ⛔ 主持判「需不需要」——2026-08-21 创始人直令改判,原选答形态见 §四 改判记)**、R2 事实类分歧点状调研、R1 提案标缺出任务单。

**按调研类型配型**:

| 类型 | 配型 | 理由 |
|---|---|---|
| 技术方案类(GitHub 上别人怎么解 X) | **gpt-5.6-luna(`max`,须显式指定 ⛔ 默认 medium)**(创始人 2026-08-21 直令「用 luna max」,转述锚在原话档;原 Opus 5 或 terra 停用) | luna 支持 max 档(高于 terra 现用 xhigh),消化判断主力;⚠️ **通道注记(cb 当轮实查 feature flags)**:codex 系**无原生网页搜索**(search_tool removed/web_search deprecated/standalone 未上线,仅 browser_use stable)⇒ **检索与消化分离配型**——检索走 claude 通道(WebSearch/WebFetch)或 browser_use,luna max 席做消化判断成包,⛔ 默认一个 luna 席端到端。**🔁 通道更新(2026-08-21,创始人令 cb 装,实测通过)**:codex 侧已接 exa MCP(hosted 形态零本地可执行零 API key,走专线出口;`web_search_exa`+`web_fetch_exa` 端到端实证)⇒ 前提已变,~~分离条暂保留——合并候选,触发=luna max 端到端跑一次真实调研包且质量五律 2(带源必查)/4(查无照报)复核过关,有数据再改~~ ⛔ 因通道通了假定质量够。**🔁 合并生效(2026-08-21,局五外证首考,方案窗口十九任裁)**:触发条件实测成立——luna max 端到端出包,relay 审注五律 2 过(92 处源锚/15 域名,抽最易编造四处四中零编造)、五律 4 过(五条否定性查无全如实);**技术方案类默认=luna max 端到端**(起席脚本 config 级 MCP 仅放 exa),**分离形态(检索 claude+消化 luna)降为后备**(通道故障或审注不过关时用);⚠️ 本次工具口径无自述一格如实记档(质量为直接读数、工具口径为代理指标不承重),调研包模板补「检索通道自述」一行(失败样本=本案,授权-2 2026-08-21);沿革记台账 |
| 体验对标类(58/闲鱼/大厂页面怎么做) | claude+browser-harness(**技术必然例外**,luna 直令不覆盖) | 真走查+截图+**视觉理解**,仅 claude 有视觉通道 |
| 长材料消化(规范全文/多报告汇总) | kimi k3(技术适配保留) | 1M 上下文整吞 |

多路并行是成熟打法(multi-modal sweep):同一问题可双路(外网+本地)互补盲区。产物=调研包(按 [[11C-调研包模板]]),入议题档材料指针,沿乙表审注纪律(引用前读审注)。

## 四 外证律:无外证不开局(**每局适用**)
