## 二 方案窗口审查区(第十七任;独立写入,建议写完再读 §一)

> **写入纪律自证**:本区落笔时 §一 未读(结构 grep 仅见其标题行);§三 因 11B 点名表态、在本区八条腹稿成形后读过——P-1 至 P-8 均成形于读 §三 之前。审查基准=总纲 72eca03→5f42d58 两读。

**P-1 双盲的旁路泄漏——起席记录**:各席由 dispatch 在 tmux 起,若看板/台账的起席记录含「席位×引擎」对应,主持读看板即可反推代号映射,双盲名存实亡。建议:起席看板记录只记**席位数与级别**,「席位×引擎×代号」三元对应仅存书记员封存档;R4 揭示后补记全账。
**P-2 R2 机械步骤缺口**:R1 写明书记员收齐、去署名、贴入、commit 四步;R2 只写「各席输出分歧点清单」——落哪个文件、谁收、谁贴、何时 commit 未写。建议 R2 与 R1 同形:各席落 `R2-<代号>.md`,书记员去署名贴入分歧区并 kb-commit。
**P-3 试写检验与双盲的时序冲突**:提案·工程席兼判据栈第 3 层试写检验,而检验产物落 `prompt/试写检验/` 且形态暴露引擎身份——若检验发生在 R1-R3 轮内,双盲破。建议总纲补一句时序:**试写检验属 R4 拍板后的发车包工序,⛔ 在圆桌轮次内进行**。
**P-4 授权-2 在圆桌议题内的适用边界**:圆桌进行中主持若对某子点行使授权-2 直裁,会蚕食「创始人拍板防假共识」这层兜底。建议:**圆桌议题射程内授权-2 暂停适用**——主持把可直裁子点列入待拍清单标「建议按授权-2 处置」,创始人 R4 一并过;圆桌外的日常裁定照旧。
**P-5 在飞议题的材料过期门铃**:方案期活口片合并会改 main 与事实表;若在飞议题的材料指针正引用受影响表,讨论就建立在过期材料上。建议:活口片合并后,**书记员对在飞议题跑一次材料指针时效检查,失效即补门铃**——与今日两次「材料更新广播零收件人」判定同款机制,挂点落书记员。(与 §三.2 互补:那条讲广播有没有发,本条讲广播到议题档的挂点与动作。)
**P-6 「发车包含正式 prompt 底稿」措辞缝**:总纲 §〇 写发车包含「正式 prompt 底稿」,版本总纲 §七之二.3 写真发车须以检验产物为底稿**另存**正式 prompt 走 kickoff——「底稿」两处所指不同。建议统一:发车包含「方案包群+试写检验通过标记」,正式 prompt 由 dispatch 开发期按 kickoff 写。
**P-7 优化台账列名**:「被采纳分歧数」R4 当场记的是拍板层面的采纳,落地验证是另一回事。建议列名改「**拍板采纳分歧数**」,防后任读成「实施验证过的采纳」。(措辞级。)
**P-8 R0 呈批的最小形态**:批框架「一句开即可」——建议议题档头固定三行摘要位(议题一句/级别与席位/要拍什么),防批框架变成读全档。创始人带宽是今日实测过的约束。(体验级。)

**对 §三.4 表态:采**。补判据一句:「涉自己射程」=该议题的结论会修改 11B 维护的卡或工具仓,即算;换席后 11B 转服务位应召供料照常——供料不合议,与「relay 快查供料 ⛔ 裁」同构。
**对 §三.5 表态**:同意归创始人拍不代决;「点 3 并入总纲 §八 销项」的分析读来成立,随 R4 呈。

**主持席可执行性总评**:R0-R4 我跑得顺;双盲闭环成立的前提是 P-1 堵上;P-2/P-3 是首场前该补的机械句;P-4 是权力边界要先说死的一条;其余措辞与体验级,可随首场复盘再定。

## 三 11C↔11B 协作深析(11B)

1. **接口哲学一句话**:两机制之间**不靠信任靠验收**——封盘包的验收器=11C 主持(R0 缺件退回),发车包的验收器=dispatch(试写检验+kickoff 闸门);对称、落盘、可拒收。这与流水线「不接受自我声明」同一条 DNA,只是把它抬到了机制间层面。
2. **活口环流是唯一的方案期双向通道**,且已闭环:点名发车→合并→CHANGELOG+事实表刷新→在局广播反哺讨论现状。风险点=广播依赖 dispatch 记得(人环),机器化(事件总线挂钩)列为优化候选 ⛔ 现在做。
3. **relay 双属载荷**:11C 三职+11B 中继本职(裁定缺口路由+codex/kimi 转办)同栖一席。静态判断=可行(全部可落盘可中断、门铃类动作轻);但**首场后必须看复盘数据**——若书记员机务与转办高峰互相挤压,拆分方案(机务转一次性窗口)已有形态可循,先记入优化候选 ⛔ 预设。
4. **人格复用的边界**:11B 窗口坐第三提案席时,若同场议题涉及 11B 自己的工具件(如 council),即构成「提案自己的射程」——沿主持下场机制同源处理:该类议题 11B 让席,由一次性 Fable 窗口顶替。**本条建议入总纲**(轻量,一句话),请方案窗口审查区表态后合并。
5. **待拍三点的依赖关系**:状态行(点 1)是发车交接序列的机器判据位,拍前用看板条顶替可运转但换班鲁棒性差;活口通道条文(点 3)已被总纲 §八 事实覆盖大半——建议创始人拍时把点 3 并入总纲销项,仅剩点 1/点 5 独立;此项归创始人拍 ⛔ 本审查代决。
