##### 二 判据 1:正典与过程档的分离形态

###### 2.1 分类定义(判据句:哪些是「当前怎么做」,哪些是「为什么这么定」)

- **正典(消费面,「当前怎么做」)**:机制总纲类(版本管理总纲/B 件/11C-圆桌总纲/开发协作流程/知识库构建规范/各线总纲)、活账类(执行总表/流水线看板/窗口角色注册表/裁定池/红线/词表/模块台账/失败样本总账/手册类)、生成物(索引/生成/)、模板类。判别句:**它过期的方式是「被原地改写」,不是「被下一份取代」**;生命周期=改判即更新,status=active 直到 archived/superseded。
- **过程档(历史,「为什么这么定/当时发生了什么」)**:议题档、调研包、换班快照、dated 事实包/盘点/报告、原话档、开发记录、记录/、prompt/。判别句:**它带时点锚(日期/任期/基线),写完即定格,后档不推翻它的「记录价值」**;生命周期=落卷定格,没有维护义务(构建规范「全部可改」裁定不变,但过程档的改=例外非惯例)。

###### 2.2 落点与寻址方式

- **正典落点=原位**(各层现有位置;4-开发层根级瘦身后只留正典)。**寻址=index.md + 索引/ + wikilink 短名**——现状即此,零改动。
- **过程档落点=集中归宿**:4-开发层新增一个 `过程档/` 目录,下按族分:
  ```
  4-开发层/
  ├── (根级:11 份正典/活账,不动)
  ├── prompt/ 记录/ 11C-圆桌/ tools/   (全部不动)
  └── 过程档/
      ├── 换班快照/        ← 19 份
      ├── 盘点与报告/      ← 9 份 dated 过程档
      └── 设计要点/        ← 9 份设计介于档(默认不动,见呈拍点 1)
  ```
  **寻址=路径自描述(目录=族)+ 档名日期(既有惯例)+ git tag 版本回溯**;**⛔ 逐份进 index.md 登记**(index 逐份登过程档必然变陈——index 现只登正典与少量指针,此惯例条文化;过程档靠目录与 grep 寻址,这正是 AI 消费者的实际用法)。

###### 2.3 选型(呈拍①):三案并陈,推荐 A

- **A 案·族目录(推荐)**:如上,按「族」分过程档。版本维度**不由目录承担**,由 git tag + 档名日期承担(见 §三)。

###### 4.1 验证法总述:三个可跑探针 + 一个 git 证明(全部命令化,⛔ 肉眼)

1. **不重打 V0.1。** `laixin-kb-v0.1 @ ba576c6` 保持原对象与注记；它如实保存“底座定稿时的平铺库状态”。迁移后，`git show laixin-kb-v0.1:"项目入口/来信平台/知识库/4-开发层/记录/<旧路径>"` 仍按旧路径取史料，这是预期，不是断链。
2. **目录不是真相源。** 当前树中 `过程归档/V0.1/` 是便于读当前库的重排结果；版本归属、跨版 diff 与历史回溯仍只认平台版本号和 `laixin-kb-v0.y`。
3. **后续版本的时序。** V0.2 开发期间照旧写入 `prompt/`、`记录/`。封盘各既有件已完成、所有相关片已不在飞后，先按迁移清单 `git mv` 到 `过程归档/V0.2/`，完成校验，再走已定的 `laixin-kb-v0.2` 收尾针。这样不改 11B 流水线的在飞行为，且 V0.2 tag 自然包含归档后的结构。
4. **失败降级沿用已拍规则。** 归档校验未过时，不能把部分搬迁伪装成完成；记“结构归档待补”，保留原路径并在下一局/R0 核。它不反向改写局四对 tag 的“收尾针、非封盘闸门”裁定。

##### 三 V0.1 迁移分步与每步验证

| 步 | 做什么 | 可跑的通过判据 |
|---|---|---|
| 1. 建基准，不搬文件 | 从执行总表、交付/验收结论与 code `v0.1` 建 `from → to → version evidence` 迁移清单；同时记录迁移前链接校验结果和标题清单 | 清单每行都有来源；无来源的文件不在清单。`git rev-parse 'laixin-kb-v0.1^{commit}'` 仍为 `ba576c6` |
| 2. 先上校验器 | 用标准库写一个只读 `kb_archive_verify.py`：解析实际 Markdown 的 wikilink/别名/路径/`#标题锚`，跳过 fenced 与 inline code；输出解析失败集合、同名歧义集合、锚缺失集合及标题清单。现存误报以“迁移前基准集合”管理，验收的是**新增**问题为零 | 校验器对迁移前树先跑出基准；对故意把一条目标路径或标题改坏的临时副本必须报错，恢复后回到基准。不能用裸 `grep` 的零命中代替此检验 |
| 3. 试迁一小批 | 只迁一组已经闭合、清单证据完整的 V0.1 prompt 与其对应记录/证据目录，统一 `git mv`；同批改写绝对路径和路径式 wikilink，文件名与标题不改 | `git diff --name-status --find-renames` 中清单文件均为预期 rename；旧绝对路径逐条零命中；校验器无新增解析失败/歧义/锚缺失；`git diff --check` 通过 |

##### 四 Obsidian 日常阅读的取舍

默认推荐是：日常仍从根 `index.md` 看当前规则与状态；查某次 V0.1 交付为什么这样做时，才点一次“V0.1 过程归档”，或用 tag 回溯。当前页面路径不变，创始人日常阅读不需要学习新路径；历史材料多一跳，但不会再和在飞材料混在同一目录。

这项取舍应呈 R4 明示：

- **采本案**：当前阅读零迁移，历史阅读多一跳，换来过程与正典不混；

##### 五 外证范本的适配，不照抄

1. **PEP/ADR 的“过程档保留、当前正式说明另有消费面”**（外证包 a.6、c.1，来源为 PEP 1、AWS ADR）：本库只借“旧过程不代替当前正典”的关系，不借其不可变正文或统一状态机。**为什么适配本库：**本库已明确 wiki 页可改，且 AI 主要误读风险正是把旧 prompt/验收记录当现行规则；维持可改的正典并归档过程，正好解决该风险而不违反现有五层规则。
2. **KEP 的元数据/索引寻址**（外证包 a.7、a.8）：本库只借“索引须同时持有身份、路径、状态关系，不能只按编号拼路径”的教训。**为什么适配本库：**迁移会改变路径，AI 又不会凭肉眼发现锚断裂；迁移清单的 `from/to/版本依据` 与链接校验正是最小必要元数据。它不引入 KEP 的完整状态机——外证包已如实查无跨项目统一状态词表。
3. **Docusaurus 的 current + versioned docs**（外证包 b.1）反向使用：不复制整棵文档树，而保留 current 正典并用既有 Git tag 供历史快照。**为什么适配本库：**本库没有多版本并行服务的读者，且已有 `laixin-kb-v0.y`；整库副本会污染 AI 搜索面、重复内容并增加维护，收益为零。
4. **Jetpack/Nx 的项目空间分组**（外证包 e.1、e.2）：只借“目录是导航和责任边界”，不照搬 `projects/`/`tools/` 整体重构。**为什么适配本库：**现有五层与索引已是稳定入口；在开发层增一个按平台版本的过程归档边界，足以消除 V0.1 平铺问题，改动远小于重排全库。

外证包 c.4 与 d.5 是其自标的跨来源归纳，本提案没有把它们伪装成任一官方的单点结论；拍后补查包仍为 `待审注`，也不作为本案依据。
