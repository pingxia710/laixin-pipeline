# 多 Agent 对话模式调研摘要(2026-08-20,11B 调研代理网络实查;为 11C 圆桌方案的出处档)

> 调研方式:WebSearch/WebFetch 实查(2026-08 时点),非训练记忆;另有本地旧调研对照(`Projects/Development/多Agent知识库/`,2026-06-26~07-08,七条核心结论=状态管理重于分角色聊天/本地 daemon 现实路线/图与状态机是可靠性底座/skills 宜精不宜多/证据链重于自我汇报/人工介入变审批关卡/evals 必需)。

## 一 框架编排逻辑现状

2025-26 业界从「LLM 自选发言人的自由群聊」整体转向「显式工作流/图编排」。AutoGen 2025-10 与 Semantic Kernel 并入 Microsoft Agent Framework(2026-04 发 1.0),官方明言旧 GroupChat speaker-selection「不透明、难观测」是重构动因;社区分叉 AG2 仍维护经典 GroupChat(auto/round_robin/random/manual/自定义五种选人,终止靠 max_round/TERMINATE)。LangGraph 三模式 supervisor/swarm/network,官方基准 swarm 略优(supervisor 转译层丢信息)。CrewAI hierarchical 的 manager 委派有已记录缺陷,实践多用 Flow 显式编排。MetaGPT/ChatDev=SOP 角色流水线,重心已转 AFlow 与商业化。OpenAI Agents SDK(Swarm 继任)以 handoff 去中心接力。Anthropic 研究系统=orchestrator-worker(较单 agent +90.2%,耗 15 倍 token);Claude Code 2026-02 实验性 Agent Teams 引入共享任务列表+mailbox。
主要来源:visualstudiomagazine.com/articles/2025/10/01(MAF 合并)· docs.ag2.ai(GroupChat)· langchain.com/blog/benchmarking-multi-agent-architectures · towardsdatascience.com(CrewAI manager 缺陷)· openai.github.io/openai-agents-python · mindstudio.ai(Agent Teams)。

## 二 结构化 vs 自由群聊

共识已成:无结构群聊不可靠,需 orchestrator/显式流程。MAST 失败分类学(NeurIPS 2025,arxiv.org/abs/2503.13657)分析 1600+ 轨迹归纳 14 种失败模式三大类(系统设计缺陷/agent 间失配/验证缺失),结论=改设计比换模型有效。Cognition《Don't Build Multi-Agents》(cognition.com/blog/dont-build-multi-agents):所有参与方须看到完整上下文与决策痕迹,⛔ 靠摘要转述。已记录失败模式:话题漂移、互相附和、无限循环互谦、过早终止、假共识。

## 三 多模型异构合议

MoA(arxiv 2406.04692):proposer 分层+aggregator 综合,选型两准则=性能+多样性。**反证 Self-MoA(arxiv 2502.00674):混入明显弱档拉低平均质量,单强模型自采样反超混合 MoA 6.6%——异构仅在各模型实力相当/互补时占优。**辩论研究:异构组保留分歧、延缓过早共识,同构组易集体从众;RLHF 重的模型会放弃正确答案跟随多数(附和传播,arxiv 2509.23055 等)。裁判偏差:自我偏好偏差跨架构存在(arxiv 2410.21819)、位置偏差系统性存在(arxiv 2406.07791)。实践范本:Karpathy llm-council(github.com/karpathy/llm-council)——各模型独立答→**匿名**互评排名→主席模型综合;匿名化专治厂牌偏好。

## 四 黑板/共享记忆

黑板模式 2025 在 LLM 多 agent 研究中正式复兴且有实证增益(arxiv 2507.01701:依黑板内容选中 agent、循环至共识、token 更省;arxiv 2510.01285:中心发帖+子 agent 认领,端到端 +13-57%)。「markdown 文件/git 仓库作共享介质」已有多个实践先例(tick-md 单文件协调、markdown+git wiki 作 agent 共享知识层)。跨厂商标准:A2A 捐 Linux Foundation(150+ 组织)管横向,MCP 管纵向;**本地轻量场景不必上协议,文件黑板即可**。

## 五 轮次·终止·人在环

最有效结构=**独立盲答→匿名互看互评→修订→聚合裁决**;过早互看会锚定首个答案;约 4 轮饱和,3 agent 起效、5-7 后递减(arxiv 2506.00066 等)。终止=轮次上限+共识/让步检测+裁判或人类兜底三层叠加;医疗多 agent 审计实证「假共识」风险——**一致≠正确,需外部裁定**(arxiv 2510.10185)。人在环标准三位置=计划批准前/高风险动作前/最终裁决点(LangGraph interrupt() 为范式代表);⛔ 人类逐轮当主持。

## 六 十条可搬结论(已内化进圆桌方案稿)

1. 发言次序确定性阶段制,⛔ LLM 自选发言人;2. 首轮盲答;3. 互评匿名化;4. 3-4 轮封顶;5. 强制分歧输出 ⛔ 空泛同意;6. 聚合者用最强模型且与提案者分离;7. 黑板文件结构化分区(提案/分歧/已决),⛔ 纯长流水;8. 每席每轮读全量上下文 ⛔ 摘要转述;9. 共识≠正确,终止三层缺一不可,全体一致反而触发质疑轮;10. 人类节点固定两处(批框架+终裁)+中途插话权。
