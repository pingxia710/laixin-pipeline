# 独立验收卡(2026-08-29 换轴;原 285 行全文在档案档,一字未删)

> AI 验收不是程序验收的缩短版,是换一个观察面做**真实目标挑战**:不重读报告、不重复程序审计。本卡 ≤90 行 / 5000 B,加一条先删一条。

## 一 审查面(三行,机械)

- 在独立 worktree 或 ref 级操作,不进开发方正在用的工作树。
- 先 rebase 到当刻 main(这就是最终基点);`git merge-base --is-ancestor main <branch>` 不成立的分支退回。
- 界面走查用 `browser-harness`;验收窗起窗时 MCP 是有意全关的,找不到别的浏览器工具是正常态。

## 二 四问(验收本体,每问写「成立 / 不成立 + 读数」)

1. **目标结果出现了吗**:prompt 说要产生的东西——页面、接口、数据、状态——去看它本身(落库值、响应体、渲染出的页面),不看退出码、不看报告说它有。
2. **真实动线走到终点了吗**:沿 prompt 的动线自己走一遍到终点(界面片 browser-harness 真走;消费者侧无痕环境),读数进回执。**假绿在这里现形**:看似成功但目标分支根本没被触发,就是没走到。
3. **越过约定边界没有**:`git diff main --stat` 只碰动线内该碰的文件;迁移、共享配置、权限/安全面、相邻页面与接口没有意外重叠。
4. **判据不是恒绿吧**:全量测试在最终基点跑一次,判据=全部 passed 且 zero failed(⛔ 拿测试数相等当通过);只在基点实质变化或出现随机失败时重跑。缺陷修复类:本片带的回归绊线拆掉修法应变红——UI 文案、纯配置、文档类不适用。

报告里的话不当证据;两个人读同一份二手材料会一起判错——你要换的是观察面,不是再读一遍。

## 三 结论与回执(机器契约,末行一字不差)

- 通过 → 末行 `【验收回执】通过 <verify分支名> <其commit> <所基于的main commit>`
- 打回 → 末行 `【验收回执】打回 <类型:方向性|工程>`,正文给最小可复现的失败。
- **打回只因**:四问里有一问不成立。文书、格式、报告措辞、过程偏差——记录在案,不打回。
- 方向性=设计或射程错了(挂起该轨报方案窗口);工程=实现错了(转整改)。分类权在验收窗口。
- 证据落盘:结论引用的输出 `2>&1 | tee <证据目录>/<名>.log`,派工窗口用 `laixin-lane evidence <片名>` 复查;看板用 `vlog`。

## 四 高风险场景(条件触发,读同目录附录 ⛔ 读档案档)

片涉及 资金 / 权限与可见性 / 数据库迁移 / 生产数据 之一时,按 `附录-高风险专项.md` 对应节多做一项专项验证。
