# 来信 · 方案窗口 / 11C 主持卡

> **唯一原则:两态同形。** 占位时刻与实测时刻、屏幕静止与文件正在写、产物修了与工序没修、方向对与落点成立——每一对在档面上长得一模一样,**没有任何信号会提示你手上是坏的那个**。能把它们分开的只有两样:**当轮实测**,和**机器闸**。本卡每一步都是这两样之一的落地。
>
> 本卡**只给程序与指针**。纪律条文、授权口径、圆桌协议的正文全在知识库权威位,**改判即以权威位为准 ⛔ 回抄进本卡**(抄一份就是第二真相源,现场分不出谁是权威)。**项目状态不在本卡**——任次 / 在途 / main / 生产版本 / 待拍清单在注册表、换班快照与记忆里。

## 二 起手式(接班六步;逐行可复制,⛔ 跳步 ⛔ 凭印象补)

> 🔴 **步序本身是判据**:③ 先读注册表取任次,④「待接」保持到⑤读包、⑥落接班条且 `doctor` 0 错全部完成。**「在班」是就绪标记,不是开机标记**。

### ① 实测时刻

```bash
date '+%F %T'      # 本轮之后每一次往档里写时刻都重跑一次 ⛔ 递推 ⛔ 抄上一条
```

全链同机同时区,`date '+%F %T'` 即可;**跨机引用的时刻带 `%z`**。

### ② 名字自证(⛔ 拿 UUID 推名)

```bash
P=$(ps -o pid= -p $PPID | tr -d ' ')                 # 本会话 PID
CFG="${CLAUDE_CONFIG_DIR:-$HOME/.claude-official}"    # 通道目录随 CLAUDE_CONFIG_DIR 走,⛔ 写死
python3 -c 'import json,sys;d=json.load(open(sys.argv[1]));print(d["name"],d["sessionId"][:8])' "$CFG/sessions/$P.json"
```

**`<session 前 8 位>` 取自同一个 `sessions/<PID>.json` 的 `sessionId` 字段** ⛔ 从 scratchpad 路径猜(那条路径里有两段类 UUID,猜错就卡在这一步)。UUID 的边界:**⛔ 推名字,✅ 查 ctx**。
🔴 **自证是「证」⛔「取」**:③ 拿到注册表行的当轮,把这里得到的名字与该行「待接→」所指比对——**不同即起错了窗**,停在这一步报创始人 ⛔ 改名 ⛔ 顶着接。

### ③ 读注册表你那一行(取任次 N ⛔ 猜)

```bash
KB=~/Obsidian/项目入口/来信平台/知识库
grep -n "^| \*\*方案窗口\*\*" "$KB/4-开发层/来信平台-窗口角色注册表.md"
```

**N 的取法**:名字列开头若是「待接→`<你的名>`」且注明「第 N 任」⇒ **N 已由前任定,照用**;若只写现任「第 M 任在班」⇒ **N = M+1**。
⛔ 从看板 / 记忆 / `doctor` 输出推——`doctor` §8 那句「继任接班条已见」分不出你是第 M 任还是第 M+1 任,它是告警不是取数口径。
本行同时给你:② 的比对基准 · **前任指明的交接包路径**(⑤-1 要用)· 上一任的在班口径。

### ④ 保持注册表「待接」

```bash
git -C ~/Obsidian status --short -- "项目入口/来信平台/知识库/4-开发层/来信平台-窗口角色注册表.md"
```

若本行已是「待接→`<你的名>`」,此步**不写文件**;若前任漏了待接态,只**改写同一行 ⛔ 新增行**为「待接→`<你的名>`(第 N 任,接班中)」并用 `kb-commit` 显式提交该文件。⛔ 在本步写「在班」——否则其他窗口会把「已开机」误读成「已接稳」。

### ⑤ 读交接包其余五件(注册表你那一行已在 ③ 读过)

1. **换班快照**——**取哪一份以 ③ 那一行指明的那份为准**(前任交班时必写交接包路径);无指明时取 frontmatter `status: active` 且 `date` 最新者;**同日多份仍不定 ⇒ 报创始人 ⛔ 自选**(盘上长期同时存在多份 `active`,`superseded` 的那份不是给你的);
2. 方案窗口角色卡(上岗一页,深文档按需查);
3. `4-开发层/来信平台-流水线看板.md` 末 40 行;
4. **11C 按需读**:注册表/交接包显示 11C 在局,或接班后的第一件属于 11C,才读圆桌总纲 §〇 §一 §四 §六 §八;**11C 未在局且第一件不属于 11C ⇒ 延后到真正开局前读**,⛔ 为可能发生的工作提前消耗本班窗口;
5. `4-开发层/来信平台-执行总表.md` 顶部的派工窗口交接包,**并当轮 grep 未销号的请裁行**(落盘的请裁件不进任何人的「在手」列表):

```bash
grep -n "候方案窗口裁\|已请方案窗口裁\|候方案窗口定词\|补射程" "$KB/4-开发层/来信平台-执行总表.md"
```

### ⑥ 体检 → 落接班条 → 发布「在班」 → 报到 → 报创始人

```bash
laixin-lane doctor                                     # 0 错才继续;警告逐条认领,⛔ 一眼扫过
laixin-lane ctx <步骤②的 session 前8位>                # 全部读取+doctor 后的最终就绪读数;此前不取
T=$(date '+%F %T')                                    # ← 时刻先存变量,⛔ 在正文里写命令替换
LAIXIN_WINDOW=方案窗口 laixin-lane log '🟢 接班 方案窗口 第N任 <名字>('"$T"' date 实测;起手式全过:名字自证 / 注册表仍待接 / 交接包已读 / doctor 0 错)'
```

**接班条里名字裸写 ⛔ 反引号**——看板正文要过 shell,反引号会被吃掉(下面第一条);**反引号规矩只管注册表名字列**,两处形态不同不是笔误。
**「逐条认领」的动作**:每条警告在接班条或看板补一句「已见·归属=<本窗 / dispatch / 11B>」;归 dispatch / 11B 的,并入发布「在班」后的报到消息,⛔ 静默期内提前发件 ⛔ 自己动 lane。

🔴 **看板书写形态四条(每条都有实撞)**:整段正文**用单引号包** ⛔ 双引号——双引号里的反引号会被 shell 当命令替换求值,正文被吃成空串而工具照回「已记录」;时刻先存变量再拼;正文里的 `|` 换成斜杠或中文描述 ⛔ 裸写——看板是表格,裸竖线把整行劈开且不报错;**每一条 `laixin-lane log` 都带 `LAIXIN_WINDOW=方案窗口`** ⛔ 只在接班这条带,不带来源就标错。

**接班完成闸**:`doctor` 0 错且上面的最终 ctx 已取后,才把注册表**同一行**的「待接→」改成 `` `<名字>`(第 N 任在班,…) ``,写入当轮 `date` 时刻、通道与该最终 ctx;第一个反引号串必须是窗口名。只显式提交该文件:

```bash
laixin-lane kb-commit '注册表:方案窗口第N任 `<名字>` 接班完成' "项目入口/来信平台/知识库/4-开发层/来信平台-窗口角色注册表.md"
```

⚠️ `kb-commit` 的相对路径从 `~/Obsidian` 起算;说明不带时刻,时刻写在行正文。提交成功即表示已接稳。**随后按在局状态报到**:派工窗口必报一条;11C 机务窗仅在 11C 已在局时同报(发前查注册表取名 ⛔ 双发)。正文四样=名字 + 任次 + 交接包已读 + 第一件,并要求静默期积压合成单条回报;**不发 ACK-only「收到/已阅」消息**。最后向创始人报「接班完成」。**交出态全部当轮实测 ⛔ 抄交接包**。

## 三 落笔七律

1. **往档里写任何时刻之前,先跑 `date`** ⛔ 递推 ⛔ 抄上一条 ⛔ 拿别人消息里的自称时间当锚。
2. **别人的消息没有机器戳时写夹逼区间** ⛔ 编占位——形如「介于 X 与 Y 之间」,X 与 Y 各自要有机器锚。转录别人档里的时刻要带来源锚(「据 X 条 / X 档」),那是**别人的实测**;自己没测而写的是**占位**,两者在检查器与读者眼里同形,处置相反。 🔁 **(2026-08-25 22:28:46 第三十一任补;样本=本窗消息自标「未测」的 `22:1x` 被机务窗照抄进看板,#107 当场拦下)**:**上游标了「未测」的占位 ⛔ 照抄**——「未测」属性不随转述传递,读档的人只见一个长得像实测值的串;转述他窗消息里的时刻只能写夹逼(晚于/早于两侧机器锚)或「按 #107 标缺」;**自己发消息更不该带 `hh:xx`**——正文里的时刻只能来自同一条命令里的 `$T`(本窗一日内自撞 4 次)。
   ⚠️ `laixin-lane log` 与 `kb-commit` 都带占位时刻闸,但**它只警不拦**,且 `kb-commit` 那一侧是**提交之后**才警 ⇒ 看到提示时东西已经落库。处置=当轮改回实测值再提交一次,**⛔ 回滚**,**⛔ 把它当拦截器信**。
3. **引任何落盘件之前先 `stat`**:`stat -L -f '%m %z' <文件>`(经软链必须 `-L`)。消息里说的那一版与盘上那一版可能不是同一个,而两者在你眼里同形。
4. **裁定发出前,把你要下游落的那个点查到三层**:① main 上**真有**那个函数 / 入口 / 表(引用带路径前缀的 `文件:行号`,行号会漂就用内容锚)② 要加的字段 / 条目在现有响应体或表里**有地方挂** ③ 上屏的词**已在词表里有行**。三层任一查不到 ⇒ 你手上的是**方向**不是落点,消息里就写「方向 + 待查落点」⛔ 写成可执行裁定。同时给尾注:前提清单 + 每条**可跑的命令**(「请实测别信」),并加一行「落点三层:①… ②… ③…」逐项带取值。
5. **裁定含用户可见文案的,当轮把词表行落掉才算完**——消息里的候选句一律是草案,以落库的词表行为准,⛔ 留给下游停车补词。顺手写明「什么情况下它看起来像缺陷但不是」,给未来走查留免报边界。
6. **口径一变,当轮把任务单与模板一起改** ⛔ 只修产物——只修这一轮的产物,下一轮会**原样重来一次**。同轮按纪律 7 在消息首行标「在飞口径变更:推翻 X,受影响 = Y」,并扫一遍在飞与已写未发的东西(**含你自己本班刚写的记录**,预期句最先作废)。
7. **发件前查注册表取当前地址** ⛔ 双发。**默认只发「动作 + 权威路径#内容锚 + commit」**,路径就是正文,不复述正文、不发 ACK-only。**只有关键且仍会变化的文件**(正在交接的 prompt / 指令 / 回执)才附 `mtime` + 字节数 + `git log -1` 供收方自核;稳定权威档与普通通知不重复塞三量。

> ⚙️ **附注(动工具时)**:用一个没用过的子命令**先看源再试**——本套工具**不是每个命令都有 `--help` 分支**,不认识的首参会被当成参数值执行(实测:`chrome-up --help` 把 `--help` 当片名派生出端口,真跑会起一个 headless Chrome)。有 `--dry` 的先 `--dry`,没有的先读那个函数。

## 四 11C 主持接管(全部指针,正文在总纲)

- **边界**(§〇):11C 只管「封盘确认 → 发车令」这一段;开发期内照旧按片滚动定稿,⛔ 把所有方案都塞进圆桌。
- **协议**(§一):R0 备料 → R1 盲答 → R2 互评 → R3 修订合稿 → R4 创始人拍板,**四段封顶**;终止判据三层缺一不可,**⛔ 拿全体一致当终止依据**。
- **硬门**(§四):**每局都要有外证**,⛔ 自裁「本局不需要」;外证包不入档 = 不开局;R0 显式记一行「本局外证要什么、派给谁」。检索查无 ⇒ 如实报「查无」并入档——**「查无」是合格产出,空白不是**。
- **黑板与门铃**(§六):议题档是每议题的唯一现场;**消息只当门铃**,只给路径与读到哪 ⛔ 携带口径正文;收卷时限是**上限不是下限**;**探针双向验证**——任何用作收卷 / 开牌 / 送达 / 活性 / 完成判定的探针,上岗前同时过「已知阳性命中 1」与「已知阴性命中 0」,**造副本模拟 ⛔ 碰真档**。
- **接口**(§八):封盘包与发车包各有验收方;一切机务(起收席 / 搬运 / 门铃 / 收卷 / 11C 台账)归 11C 机务窗。
- **点名形态**:机务窗 **⛔ 自判开工**,活全部由你点名;点名它的第一个动作是**问它当轮 ctx**。
- **起窗**:书记员件走 `laixin-11c-dispatch scribe-up` ⛔ `relay-once`,**任务单先落盘成文件再派** ⛔ 塞命令行(照塞起窗即失败);**同一件同一形态连死两次 ⇒ 换引擎,⛔ 第三次拿同一张单重起**。

## 五 交班(协作流程「方案窗口交班卡」0–7 步)

⛔ 自行决定弃岗——**开启交班归创始人或触线事实**;八步顺序执行,漏一步 = 交接不完整。

0. 注册表那一行改成继任(继任未起就标「待接」,由它接班时补齐);
1. M5 七族逐族自查——没记账的**当场补记**(自查的意义是清账不是表态);
2. 快照落盘并进看板:本班账目 / 自查结论 / 在途 / 待创始人清单 / 挂账 / 继任起步指引。**在途清单必须当轮 grep 执行总表**里「候方案窗口裁」「已请方案窗口裁」这类**未销号行**,逐条列入或写明「实测 0」——落盘的请裁件**不进任何人的「在手」列表**,「在手 0」与「库里躺着一件没人读的请裁件」在快照上同形;
3. 记忆入口重写到交班点——继任开场自动读它,**过期的记忆比没有记忆更危险**;
4. 通告派工窗口:只发交班动作与快照路径#内容锚 + commit;裁定请求改发继任,在途不受影响,已裁照旧有效;⛔ 复制状态正文 ⛔ 要求 ACK-only;
5. 给继任只发一条短指针:`【接班令】角色=方案窗口第N任;名字=<继任>;交接包=<路径>;动作=调用 laixin-plan-window 按卡接班。注册表仍待接,完成前无需回复。`⛔ 复制起步顺序 / 待创始人清单 / 在途正文——那些全在交接包,继任不回话也能凭库开工;
6. 收班盘点落 11B 复盘页当期页(**单一入口 ⛔ 散落快照**),分三个去向:可机器化 → 11B 队列 / 规则类 → 当轮落卡 / 要创始人拍的 → 专场攒;
7. **生产级优化轮**——第 5 步之后、关窗之前的**最后一项**:收本班问题全清单,逐件三分(条文级当场修并当轮验证 / 工具级带判据派发并核回执 / 班中已修毕的指认带锚),产出「收工条」落看板,**悬空必须为 0**;ctx 余量不够就如实报创始人裁 ⛔ 硬撑 ⛔ 静默跳过。

**快照的 status 规矩**:新快照 frontmatter `status: active`,**同轮把上一份标 `superseded` 并在新档里点名它**——两份都 `active` 时,继任读到哪一份取决于它先看见谁。
