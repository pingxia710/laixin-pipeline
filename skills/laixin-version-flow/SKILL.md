> **设立依据**:创始人 2026-08-20 直令(11B 窗口当面,逐字)「**注意以前的方式不要变,咱们这个基于方案-执行的版本要另设哈**」(时刻锚=介于 A/B 件放行通报 18:5x 与本卡落盘 19:01 之间)+18:40 直令「现在是版本讨论-执行2个大节奏,跟以前完全不一样,需要配套的开发流程」(原话档午起 §三)。
> **定位**:**既有四卡(kickoff/pipeline/acceptance/deploy)=「以前的方式」,一字不动照旧执行;本卡=版本制新增工序的唯一叠加层——只加不改**。版本制机制权威=[[来信平台-版本管理总纲]](§七 方案期工作办法);本卡只给操作程序。
> **收录边界**:本卡只收录创始人**已放行/已拍**的工序。方案期机制(指挥链默认态/圆桌协议/交接指针化)已归 **11C** 承载并生效(2026-08-20 晚创始人认可),权威=知识库 `4-开发层/11C-圆桌/11C-圆桌总纲.md` ⛔ 本卡复制;仍待拍的 11B 侧三条(节奏状态行/活口通道条文化/laixin-lane 节奏机器闸)在 [[来信平台-两大节奏配套开发流程-方案稿-20260820]] §七 候拍,拍后移入本卡 ⛔ 回写既有卡。

## 一 代码管理工序(A 件五点;创始人 2026-08-20 18:4x 放行先进行,可回改;权威=[[来信平台-代码管理方案-讨论稿]],本节只给操作步)

**发车侧(写 prompt/开分支时,叠加在 kickoff 卡发车闸门之后)**:
1. **片分支命名统一 `v0y-<域>-<slug>`**(A-4;例 `v02-frontend-nickname-guard`,`v0y` 取当前平台版本号;存量短命分支不追改;单点源=本条 ⛔ 别处复制)。⚖️ **射程注(2026-08-25 10:16:34,方案窗口第二十九任,授权-2;样本=11B 第一片 `toolup-claude-print` Gate2 被 prompt-lint 以本条拦下)**:本条只管**产品仓** `~/来信平台`;**工具仓 `~/Developer/laixin-pipeline` 的工具件分支沿其既有惯例 `tool-<slug>`**(库内先例 `tool-plan-window-r2` / `tool-promptlint-date-seg` / `tool-scheme-window-skill`)⛔ 套 `v0y-`;prompt-lint 该条射程收窄归 11B 件(按 prompt 的 `--dir` 所指仓判)。

**合并侧(派工方,每片合并后,叠加在 acceptance 卡「四处台账」清单之后执行)**:
2. **代码仓根 `CHANGELOG.md` 的 `## Unreleased` 段追一行**(A-1;Keep a Changelog 式,人读的对外变更账,⛔ 替代执行总表——两者分工在 A 稿 §一.1):一句写清本片对外可感知的变更;**仓根尚无该文件时,先建档并回填 `## v0.1` 一条总账再追行**;作为独立纯文档提交进 main,⛔ 混入代码改动。

**发版侧(叠加在 deploy 卡流程上;执行者归属照 deploy 卡「执行者归属」节不变)**:
3. **封盘发版时**:把 `CHANGELOG.md` 的 `## Unreleased` 段整体落成 `## v0.y - <日期>` 段并提交(A-1 的封盘半边);🔁 **2026-08-25 14:03:46 三档发法追认(版本总纲 §一 第 6 条,创始人 2026-08-25 拍)**:热修与期中版**同样封段**为 `## v0.y.z - <日期>`(实践自 v0.2.1 起如此),~~常规部署与热修跳过~~ 作废;
4. **热修/封盘后补丁 tag=`v0.y.z`**(A-2;如 v0.1.1):生产缺陷修复走正常流水线合入 main 后打 tag 并按 deploy 卡同法推裸仓;打 tag 归属照 deploy 卡(创始人确认后方案窗口打);
5. **发版同步 GitHub Release**(A-3;仅封盘版 tag 与热修 v0.y.z tag):`gh release create v0.y --notes "<该版 CHANGELOG 段>"`——正文=CHANGELOG 该版本段 ⛔ 另写一份;仓库私有 Release 仅自己可见,给创始人一个可浏览的版本史页面。
5-bis. **期中版每日工序(C 档;权威=版本总纲 §一 第 6 条,本条只给步序)**:每个工作日 **16:30–16:45 dispatch 落冻结点**——若当日 main 领先生产:CHANGELOG 封段 `## vX.Y.z - <日期>`(先补齐漏追行)+ `facts-fresh` 刷至该 hash + 看板一条「冻结点 <hash>」;main 未前进 ⇒ 看板记「今日无冻结点」⛔ 空封段。**17:00–18:00 方案窗口按 deploy 卡执行**(预检 · 备份 · 部署 · 四判据〔HEAD / 两服务重启时刻 / 公网 `/version` / 本批新代码独有路由〕· tag `vX.Y.z` · Release · 手册记录 · 通知创始人强制刷新),**⛔ 逐次问创始人 ⛔ 每次回滚演练**;在飞验收与待合不等;创始人可随时喊停或点名立即发;生产事故当日只热修。z 由热修与期中版共用递增。 🔁 **时限型职责的主机制(2026-08-25 方案窗口第三十一任落,授权-2;样本=dispatch 第七十任 16:33 冻结点 cron 因 REPL 未空闲实际 17:03:40 才触发,冻结点靠当班人 16:38 手动落;同日方案窗口 CronCreate 与后台计时均被自动模式分类器拦下)**:冻结点与发布两个时限**以当班人盯窗口为主机制**(写进各自交接包「继任第一件」并带时刻),**会话级 cron / Monitor 只当兜底 ⛔ 当履职方式**;不依赖 REPL 空闲的机器闸归 11B 队列(到点即投递看板+dmsg)。
6. **封盘包点齐**(11C 接口,圆桌总纲 §八):封盘确认时核**五件**齐=tag+CHANGELOG 版本段+事实表刷新至封盘 main+底座更新指针+**版本沟通账**(第五件,局三 R4 增补,口径见本卡 §五.2),齐了看板记「封盘包成」一条——它是 11C「版本更新账」议题的开局材料,缺件会被 11C 主持 R0 退回。
7. **在局广播**(方案期活口片专用):方案期内若有 11C 议题在局,合并推进 main 后 dispatch 门铃书记员(relay)「main 前进,事实表已刷新」——在局讨论 ⛔ 建立在过期现状上(圆桌总纲 §八)。

## 二 真实信息源刷新工序(创始人 18:48「真实信息源」直令;形态权威=B 件[[来信平台-知识库版本级框架方案-草案]],其 §六 执行序放行)

> 刷新不进流程,信息源就是下一个静默过期的表(当日实测:四端盘点档基准落后生成物 6 小时)。

1. **合并后刷新**(派工方,叠加在「四处台账」之后、与本卡 §一.2 同轮):重跑 `4-开发层/tools/laixin_facts_export.py`(B 件模块事实页生成器化后仍是**同一条刷新命令**,⛔ 出现第二条刷新路径);**完成判据=逐表核生成物头行 `main@<hash>` 基准锚全部等于新 main**,⛔ 以退出码 0 为准(kickoff 5-bis 同源);
2. **引用侧鲜度核(对偶条)**:凡 prompt/台账引用 L1 生成物,先核头行锚=当前 main;不新鲜 ⇒ 先刷新再引用,⛔「读旧表+人工脑补差量」;
3. **读物采信**:按 B 件 §一 三层架构——L1 生成层>L2 规则锚定层(未锚定规则用前必核代码)>L3 档案层(先查 frontmatter status);事实源=导航与断言底稿,⛔ 替代 kickoff「去现场与枚举标准」的现场核;
4. **生成器扩展**(模块事实页七模块+规则表节嵌入):商会样例已验证形态(2026-08-20 `索引/模块事实页样例-商会-20260820.md`),由 11B 接手生成器化(B 件 §六 执行序 2→3);**需求清单=样例页 §五 手工拼装暴露的 5 条**(依赖注入式门控捕捉/service 层权限标注/chamber_relationship 状态机导出/按消费点归并模块 ⛔ 按路由前缀/词表按模块过滤);完成判据=样例页与生成页逐节 diff 一致+「AI 能通」五条自检+样例页 §五 待核件逐条核销或显式移交。

## 三 档案层 frontmatter 工序(B 件 §四;改档侧+建档侧一对)

1. **任期档收尾动作(改档侧,B 件 §四.6;条文归 11B,存量 11 份批改由 relay 随 frontmatter 归一执行)**:凡新任期档/换班快照/交接包档生效,交班方(接班方代登同可)**同轮把上一份任期档 frontmatter 改 `status: superseded` 并加 `superseded-by: <新档名>`**——AI 读库按 frontmatter 过滤采信,旧档不改标就会以在班口径被读到;
2. **新建档约束(建档侧,B 件 §四.8;relay 归一实测「移动靶」后立)**:任何窗口新建知识库档,frontmatter 的 `status` 只用 4 枚举(active/draft/archived/superseded)+`stage:` 表成熟度,⛔ 新造 status 值——否则归一永远追不上建档。

## 四 与既有卡的关系(防漂移)

- 本卡工序全部是**叠加步**,⛔ 修改既有四卡任何条文;发现本卡与既有卡冲突 ⇒ 报方案窗口裁,⛔ 自行折中执行;
- 待拍条文拍板后一律**入本卡**,⛔ 回写既有卡——创始人「以前的方式不要变」直令既是本卡的存在理由,也是它的边界;
- 本卡与版本总纲冲突,以总纲及创始人后令为准(改总纲归方案窗口)。

## 五 开发期计数位与沟通账(局三 R4 增补;创始人 2026-08-21 09:16「10条都过」;详案与实证=[[议题-版本制沟通成本解法议定-20260821]] §四)

1. **计数纪律条**:凡进台账/验收报告/封盘包/圆桌材料的计数断言——四栏落盘(量|当轮值|**可原样重跑的命令**|口径与已知偏差),印文一律可复跑、示意须显式标;非机器口径则**双探针互核且两探针形态独立**(同形不算互核);零计数与骤降必做阳性自检;**与权威源逐字一致 ⛔ 构成免检**。(失败样本六例在议题档;总账通则区有对应句)
2. **版本沟通账**(封盘包第五件):每版封盘按七项固定口径跑一遍、命令原文连同落入封盘包——①⑦开发期/方案期窗口内看板事件数 ②打回动词位 ③合并+首过率(lane stats) ④停车动词位 ⑤口径变更动词位分节奏 ⑥总账族分布净增(**标「下界代理」**;E 族净增归方案期账页)。窗口切法=发车令→封盘确认为开发期(**收盘段计入开发期**)、封盘确认→发车令为方案期,锚取原话档机器时刻;首版立基线次版起可比 ⛔ 硬造对比。
3. **停车/口径变更动词位**:看板新增两个动词值(格式与打回/挂起同构);停车带一字归因**三选一=判据|现状|环境**——判据类回填方案包缺口账、现状类回填事实页生成器需求清单、环境类隔离出五类噪声。
4. **打回单引用条**:打回理由须引用方案包判据条目或事实页锚;引用不到照常打回但记「**判据外打回**」(硬计数)并附归因标签(判据缺|实现错|理解偏,软分布);判据外打回回填下一版方案期。
5. **开发期口径变更平移句**:发车后队列循环内口径变更同守「圈受影响件+扫存量」(总纲 §七之二.4 的开发期明示化);登记位=本节 3 的动词位;增量两动作=dispatch 圈影响面+**对在飞片发刷新门铃**(变更只指权威位 ⛔ 消息带正文)。要降的是被过期口径绊倒次数(目标 0)⛔ 变更次数本身。
6. **发车登记行带事实源锚**:dispatch 发车条/台账行带 `事实源锚=main@<hash>`,验收端第一步核锚——本条=§二.2 对偶条**前移一站 ⛔ 第二条刷新路径**;**⛔ 动 prompt 宪法头**(不改清单明列)。
7. **活口通道条文化**(方案稿 §七 待拍点随局三 R4 拍过):方案期活口=热修+扎实化,**点名单片进出**——方案窗口点名 → kickoff 全闸门 → fresh+send → 交付 → 独立验收 → ff-only 合并+叠加步 → **片毕即停**;同时在飞 ≤1;热修优先、免首批知悉。(节奏状态行落执行总表顶=dispatch 份;laixin-lane 节奏机器闸=候选池挂「可缓」)
